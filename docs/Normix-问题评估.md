# Normix 当前问题评估

## 1. 结论

当前 Normix 的功能已经比较完整，但界面复杂度超过了功能复杂度。作品库和灵感集默认都同时显示 4 个纵向区域，大量信息重复出现，用户需要自己判断“该看哪里、在哪里操作”。这违反了奥卡姆剃刀原则：如无必要，勿增实体。

当前最大的问题不是缺少功能，而是入口过多、层级过深、信息重复，导致界面看起来“很复杂、很拥挤”。

## 2. 当前布局实测

以 1440px 桌面宽度为例：

| 页面 | 当前纵向区域 | 宽度占比 | 问题 |
| --- | --- | --- | --- |
| 作品库 | 左侧主导航 / 左侧管理栏 / 作品内容 / 右侧检查器 | 232 / 220 / 608 / 340 | 四栏结构，内容区被压缩 |
| 灵感集 | 左侧主导航 / 文件夹与标签栏 / 页面内容 / 右侧检查器 | 232 / 260 / 608 / 340 | 四栏结构，页面区被压缩 |
| 灵感集内部 | 文件夹 Tab / 作品 Tab / 标签区 / 筛选栏 | 集中在左侧栏中 | 一个侧栏承担了多种管理职责 |

当前作品库实际可用的内容区只有约 608px，在 1440px 屏幕上只够展示 1-2 张卡片；大量空间被“管理栏 + 检查器”占用。

## 3. 重复与冗余问题

### 3.1 文件夹入口重复

- 作品库左侧管理栏展示文件夹。
- 灵感集左侧栏展示文件夹 Tab。
- 主内容区又展示“子文件夹”卡片。

同一份文件夹数据被三个地方反复呈现，但三者作用不同：管理、筛选、浏览。用户很难理解为什么文件夹会在三个位置出现。

### 3.2 标签入口重复

- 作品库左侧管理栏展示标签。
- 顶部筛选栏展示标签。
- 灵感集左侧栏底部有独立标签区。
- 检查器内也可以添加标签。

标签至少出现 4 次。尤其是“筛选标签”和“管理标签”混在一起，用户容易误以为点击标签会修改标签，而不是筛选图片。

### 3.3 导入入口重复

当前存在：侧边栏、作品库顶部、作品库空状态、灵感集筛选栏、文件夹右键菜单。入口过多会降低主入口的显著性。

建议保留：
- 侧边栏全局入口。
- 空状态入口。
- 当前文件夹右键入口。

顶部重复入口可以取消。

### 3.4 批量操作入口重复

作品库中批量操作同时存在于：
- 多选后的右侧检查器。
- 鼠标右键菜单。

这两个入口都有价值，但右侧检查器默认打开会让“未选择任何内容”时也占用一栏空间，导致四栏压力。

## 4. 界面体验问题

### 4.1 四栏布局过度复杂

当前结构可以概括为：

```text
当前作品库
[主导航] [管理栏] [作品列表] [检查器]

当前灵感集
[主导航] [文件夹/标签] [页面列表] [检查器]
```

用户视线需要横向跨 4 个区域，移动端又需要把 4 个区域纵向堆叠，信息密度反而更高。

### 4.2 内容区被压缩

作品库和灵感集的核心内容是作品和页面，但当前核心内容只占约 42% 宽度。用户想看更多作品时，没有足够空间；关闭检查器后体验才稍好，但这不应该依赖用户手动操作。

### 4.3 管理功能与浏览功能混在一起

文件夹、标签、作品、页面同时挤在左侧栏中，导致：

- 用户无法快速区分“组织素材”和“浏览素材”。
- 文件夹、作品、标签三种层级概念并列，短期记忆负担重。
- 每个概念都有展开、折叠、重命名、删除、拖拽，操作复杂度叠加。

### 4.4 缺少清晰的信息层级

当前顶部筛选栏、左侧管理栏、右侧检查器都包含不同信息，但没有统一的“主次关系”。用户需要同时理解：

- 左侧栏：组织结构。
- 顶部栏：筛选条件。
- 内容区：当前结果。
- 右侧栏：当前选中项详情。

这四个区域都默认同时出现，违背“减少短期记忆负担”原则。

## 5. 与设计规范的差距

### 5.1 色彩

当前界面已经收敛为黑白灰，方向正确。但问题是：

- 黑白灰过于平均，缺少明确的信息层级。
- 操作、选中、警告、成功状态没有稳定语义色。
- 检查器、筛选栏、管理栏都是白色/浅灰背景，视觉上无法区分主次。

建议保留黑白灰主体，同时定义少量状态色：

| 状态 | 建议颜色 | 用途 |
| --- | --- | --- |
| 主操作 | 黑色 | 导入、确认、主按钮 |
| 成功 | 绿色 | 完成、恢复 |
| 警告 | 红色 | 删除、危险操作 |
| 选中 | 深灰边框 | 多选、当前项 |

不使用大面积蓝色或紫色，避免与品牌冲突。

### 5.2 字体

当前字体基本统一，但字号层级不够明确：

- 标题、正文、辅助信息之间差异较小。
- 卡片内信息较多时，作品名、分类、标签、页数、文件大小都挤在一起。

建议建立明确的三级字体系统：

| 级别 | 字号 | 用途 |
| --- | --- | --- |
| 页面标题 | 15-16px | 当前视图标题 |
| 正文 | 13px | 作品名、页面名 |
| 辅助 | 11px | 标签、时间、大小、说明 |

### 5.3 布局

当前主要是“工具型多栏布局”，缺少明确的视觉引导：

- 没有清晰的 F 型阅读路径。
- 没有统一的内容网格节奏。
- 留白被多栏挤压。

建议默认采用：

```text
简化后
[主导航] [主要内容区]
           [筛选栏]
           [内容网格]
           [可选检查器抽屉]
```

检查器不再默认占用一栏，只在用户选择内容时以抽屉形式出现。

## 6. 功能重复造成的维护风险

### 6.1 状态容易不一致

同一个文件夹/标签状态在多个组件中重复维护，容易出现：

- 左侧栏选中了文件夹，但顶部筛选没有同步。
- 标签区筛选后，页面没有更新。
- 删除后部分入口未刷新。

### 6.2 测试成本高

每个重复入口都需要回归：

- 文件夹：3 个入口。
- 标签：4 个入口。
- 导入：5 个入口。

入口越多，回归范围越大。

### 6.3 新用户学习成本高

新用户打开页面后，第一眼看到 4 栏，无法确定操作顺序。建议将核心路径压缩为：

```text
1. 选择视图。
2. 查看内容。
3. 需要时打开管理/详情。
```

## 7. 优先级建议

| 优先级 | 问题 | 影响 |
| --- | --- | --- |
| P0 | 四栏变多栏，核心内容区过窄 | 影响所有用户 |
| P0 | 文件夹/标签重复入口过多 | 影响理解与操作 |
| P1 | 筛选与管理职责混在一起 | 影响效率 |
| P1 | 检查器默认常驻 | 影响内容浏览 |
| P2 | 移动端多区域堆叠 | 影响移动访问 |
| P2 | 状态色与字体层级不明确 | 影响视觉质量 |

## 8. 核心判断

Normix 不需要增加更多功能，而是需要做减法：

- 默认只保留 2 个纵向区域：主导航 + 主要内容。
- 文件夹、标签、检查器都改为可打开/关闭的辅助区域。
- 删除重复入口，只保留最清晰的一条路径。
- 把筛选、管理、详情三种职责分开，不放在同一视觉层级。

这样可以同时改善：内容浏览、操作效率、移动端体验、维护成本和用户理解成本。
