# Normix 标签系统完善开发方案

## 1. 文档目标

本方案解决 Normix 当前“作品分类标签”和“灵感图库图片标签”混用同一套标签数据的问题，目标是把两套标签体系彻底隔离，同时保持现有产品形态简单、操作路径短、视觉风格统一。

最终形态：

- 作品分类标签：只用于作品库中的作品，支持作品筛选、作品分类、首页统计。
- 图片标签：只用于灵感集里的图片/页面，支持图片筛选、图片分类、页面标签。
- 两套标签可以出现同名字标签，但数据、绑定关系、删除行为完全独立。
- 标签新增、编辑、删除、分组、排序、绑定资源都集中在左侧栏“标签管理”入口中，同时在作品/图片详情处可以直接打标签。

## 2. 当前情况评估

### 2.1 后端现状

| 项目 | 现状 | 问题 |
| --- | --- | --- |
| 标签表 | 只有一张 `tags` 表 | 没有明确区分作品标签和图片标签 |
| 关联表 | `work_tags`、`page_tags` 指向同一张 `tags` | 同名标签可能被两边同时引用 |
| 标签范围 | 通过 `tag_group` 粗略区分“自定义/页面” | 不严谨，无法保证数据隔离 |
| 删除标签 | 直接删除 `tags` 中的记录 | 会连带删除两侧关联，影响另一套标签 |
| 绑定接口 | 部分接口按标签名操作 | 同名标签容易误删、误绑 |
| 标签树 | `/api/tags/tree` 返回混合树 | 作品和图片共用同一棵树 |

### 2.2 前端现状

- 作品库中的作品标签目前以 `work.tags` 名称数组为主，缺少稳定的标签 ID 绑定。
- 灵感集页面标签已经包含 `tagIds`，但筛选和管理仍依赖混合标签树。
- 左侧栏已新增“标签管理”按钮，位于“灵感集”和“回收站”之间，点击后打开标签管理面板。
- 现有标签管理面板已经有“作品标签 / 页面标签”两个页签，但底层仍是同一套数据。
- 首页分类统计基于标签路径和虚拟分组，目前无法区分作品标签与图片标签。

### 2.3 核心问题

1. 数据边界不清晰。
2. 同名标签无法安全隔离。
3. 删除一个标签可能影响另一套系统。
4. 绑定接口按名称操作，存在歧义。
5. 标签管理入口刚接入，但管理能力仍不完整。

## 3. 目标设计

### 3.1 两套独立标签体系

定义两个固定的标签范围：

| 范围 | 名称 | 绑定资源 | 使用场景 |
| --- | --- | --- | --- |
| `work` | 作品分类标签 | 作品 | 作品分类、作品筛选、作品批量管理 |
| `page` | 图片标签 | 灵感集图片/页面 | 图片分类、图片筛选、页面检查器 |

两套标签可以拥有相同的名称，例如：

- 作品分类标签中有“重点参考”
- 图片标签中也有“重点参考”

它们是完全不同的标签记录，互不影响。

### 3.2 数据结构设计

在现有 `tags` 表上增加范围字段，尽量保持当前表结构兼容：

```text
tags
  id         TEXT PRIMARY KEY
  scope      TEXT NOT NULL DEFAULT 'work'   -- work | page
  name       TEXT NOT NULL
  parent_id  TEXT
  tag_group  TEXT
  color      TEXT
  sort_order INTEGER
```

说明：

- `scope` 是硬隔离边界，所有查询、新增、编辑、删除都必须携带。
- `parent_id` 负责标签分组和层级。
- 不强制标签名唯一，同一范围内允许重名，但所有业务操作按标签 ID 进行。
- 为了兼容旧数据，保留 `tag_group` 字段，但不再作为系统隔离依据。

### 3.3 数据迁移方案

迁移前必须备份数据库：

```bash
cp data/app.db backups/app.db.bak
```

迁移逻辑：

1. 扫描现有标签。
2. 只被作品绑定的标签：设置 `scope = work`。
3. 只被图片绑定的标签：设置 `scope = page`。
4. 同时被作品和图片绑定的标签：拆成两条记录。
   - 原记录保留为 `scope = work`
   - 新建一条 `scope = page` 记录
   - `page_tags` 重新指向新的图片标签记录
5. 没有绑定任何资源的标签：
   - 如果原本属于“页面”分组，设置为 `scope = page`
   - 否则设置为 `scope = work`
6. 分组节点按后代标签的归属拆成独立的作品分组树和图片分组树。
7. 迁移完成后执行一致性检查，输出报告。

一致性检查项：

- 所有 `work_tags` 关联的标签 `scope = work`
- 所有 `page_tags` 关联的标签 `scope = page`
- 没有残留的跨范围绑定
- 没有标签同时存在于两个范围且数据未拆分
- 作品标签名称、图片标签名称、数量与原数据一致

## 4. 接口设计

### 4.1 标签管理接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/tags/tree?scope=work` | 获取作品分类标签树 |
| GET | `/api/tags/tree?scope=page` | 获取图片标签树 |
| POST | `/api/tags` | 新增标签或分组，必须传 `scope` |
| PATCH | `/api/tags/:id` | 编辑名称、父级、颜色、排序 |
| DELETE | `/api/tags/:id` | 删除当前 `scope` 下的标签及绑定 |
| POST | `/api/tags/reorder` | 批量排序 |
| GET | `/api/tags/:id/resources?scope=work` | 查看该标签绑定的作品 |
| GET | `/api/tags/:id/resources?scope=page` | 查看该标签绑定的图片 |

新增标签请求示例：

```json
{
  "scope": "work",
  "name": "国创赛",
  "parentId": "group-id",
  "color": "#3e6df0"
}
```

### 4.2 资源绑定接口

所有资源绑定改为按标签 ID 操作。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/works/:id/tags` | 给作品添加作品分类标签 |
| DELETE | `/api/works/:id/tags/:tagId` | 移除作品分类标签 |
| POST | `/api/pages/:id/tags` | 给图片添加图片标签 |
| DELETE | `/api/pages/:id/tags/:tagId` | 移除图片标签 |
| POST | `/api/works/tags/batch` | 多选作品批量添加/移除标签 |
| POST | `/api/pages/tags/batch` | 多选图片批量添加/移除标签 |

批量绑定请求示例：

```json
{
  "resourceIds": ["work-1", "work-2"],
  "tagIds": ["tag-1"],
  "action": "add"
}
```

### 4.3 资源查询接口

- 作品库筛选：`GET /api/works?tagIds=id1,id2`
- 灵感集筛选：`GET /api/pages?tagIds=id1,id2`

作品接口同时返回：

```json
{
  "id": "work-1",
  "tags": ["国创赛"],
  "tagIds": ["tag-1"]
}
```

图片接口继续返回：

```json
{
  "id": "page-1",
  "tags": ["重点参考"],
  "tagIds": ["tag-2"]
}
```

## 5. 前端界面设计

### 5.1 左侧栏入口

保持当前“标签管理”按钮位置：

```text
首页
作品库
灵感集
标签管理
回收站
导入作品
```

收缩状态下只显示标签图标，与其他导航按钮保持相同尺寸和居中规则。

### 5.2 标签管理工作台

点击“标签管理”后打开全屏或右侧抽屉式工作台，推荐使用右侧抽屉，避免用户离开当前工作上下文。

工作台结构：

- 顶部标题：标签管理
- 顶部搜索框：搜索当前范围下的标签和分组
- 分段切换：
  - 作品分类标签
  - 图片标签
- 左侧标签树：
  - 分组可展开/收起
  - 标签显示名称、颜色、绑定数量
  - 支持新增子标签、重命名、删除、移动
- 右侧详情区：
  - 标签名称
  - 所属分组
  - 标签颜色
  - 绑定资源数量
  - 关联作品/图片列表
  - “查看资源”按钮

### 5.3 极简操作原则

- 新建标签：在工作台顶部输入名称后按回车即可创建。
- 新建子标签：在分组行右侧点 `+`，进入行内输入。
- 编辑标签：点击铅笔图标，行内直接改名。
- 删除标签：点击垃圾桶图标，一次确认。
- 移动标签：拖拽到目标分组，或右键选择“移动到分组”。
- 查看资源：点击“查看资源”跳转到作品库或灵感集并自动筛选。

## 6. 资源侧绑定设计

### 6.1 作品库

- 单个作品：在作品详情或卡片菜单中提供“作品分类标签”选择器。
- 多选作品：在批量操作栏中提供“添加标签 / 移除标签”。
- 标签选择器只展示 `scope = work` 的标签。

### 6.2 灵感集

- 单个图片：在页面检查器中提供“图片标签”选择器。
- 多选图片：在选中工具栏中提供“添加标签 / 移除标签”。
- 标签选择器只展示 `scope = page` 的标签。

### 6.3 视觉区分

- 作品分类标签使用作品图标。
- 图片标签使用图片图标。
- 标签色块沿用当前标签颜色系统。
- 不引入新的复杂设计体系，保持黑白灰主界面风格。

## 7. 实施顺序

### 阶段 0：数据安全

- 备份数据库。
- 编写迁移评估脚本，输出当前混合标签清单。

### 阶段 1：后端数据迁移

- 增加 `scope` 字段。
- 拆分混合标签。
- 增加范围唯一校验和一致性检查。

### 阶段 2：后端接口

- 标签树、标签 CRUD、标签排序全部增加 `scope`。
- 作品和图片绑定接口改为标签 ID。
- 增加批量绑定接口。
- 增加资源查询接口。

### 阶段 3：前端数据层

- `TagNode` 增加 `scope`。
- `Work` 增加 `tagIds`。
- `GalleryPage` 继续使用 `tagIds`。
- 所有标签过滤、删除、绑定操作改为 ID 驱动。

### 阶段 4：标签管理工作台

- 完善“标签管理”抽屉。
- 接入两套标签树。
- 完成新增、编辑、删除、分组、排序、搜索。
- 完成右侧资源详情。

### 阶段 5：资源绑定

- 作品库接入作品分类标签。
- 灵感集接入图片标签。
- 支持单资源绑定和多资源批量绑定。

### 阶段 6：回归验证

- 首页分类统计。
- 作品库筛选。
- 灵感集筛选。
- 标签管理。
- 回收站。
- 侧边栏收缩。
- 数据持久化。

## 8. 风险与对策

| 风险 | 对策 |
| --- | --- |
| 旧数据中同名标签同时被作品和图片使用 | 迁移时自动拆分，并保留完整备份 |
| 历史 `work.tags` 只有名称，没有 ID | 接口兼容返回 `tags` 和 `tagIds`，逐步迁移 |
| 删除接口误伤另一套标签 | 后端强制校验 `scope`，删除前检查范围 |
| 标签名重复导致前端混淆 | 所有内部操作使用 ID，名称只作为展示 |
| 首页统计依赖虚拟分组 | 改为读取当前范围的标签树和绑定数量 |

## 9. 非目标

- 不引入多用户权限体系。
- 不做 AI 自动打标签。
- 不强制标签名唯一。
- 不做标签跨范围共享。
- 不改变现有上传、文件夹、回收站、页面查看等核心流程。

## 10. 验收标准

1. 作品分类标签只能绑定到作品。
2. 图片标签只能绑定到灵感集图片。
3. 两套标签可以存在相同名称，互不干扰。
4. 删除图片标签不会影响任何作品的标签。
5. 删除作品分类标签不会影响任何图片的标签。
6. 作品库筛选只按作品分类标签过滤。
7. 灵感集筛选只按图片标签过滤。
8. 标签管理抽屉支持新增、编辑、删除、分组、排序、搜索。
9. 侧边栏“标签管理”按钮位置正确，收缩态与其他导航一致。
10. 首页统计基于正确的作品分类标签数据。
11. 全量回归：`npm run lint`、`npm run build`、`npm run smoke`、`npm run acceptance` 全部通过。
